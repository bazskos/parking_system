a parkingspotnal egy egyedi mezot ami int lenne, egy booleant ami nezi hogy szabad e vagy nem.

a bookingnal ket datetimeot egyik a nyito idopont masik a zaro, itt lenne egy string a nevnek es lenne egy id ami int

a kettot kozotti kapcsolat pedig a ket id lenne.

Nagyon jó az irány, a típusok (int, datetime, string) teljesen a helyükön vannak! Viszont a ParkingSpot táblánál belefutottál egy klasszikus tervezési csapdába, amibe szinte minden junior beleszalad az első foglalási rendszerénél. Ezt most tegyük tisztába, mert ez lesz a rendszeretek lelke.

Mi a gond a boolean is_free (szabad-e) mezővel a parkolóhelynél?

Gondolj bele: egy parkolóhely nem abszolút értelemben "szabad" vagy "foglalt". Ha én holnap 10:00 és 12:00 közé foglalok egy helyet, akkor az a hely most szabad? Igen. Holnap 11:00-kor szabad lesz? Nem. Holnapután szabad lesz? Igen.

Ha beteszel egy boolean mezőt, azt folyamatosan frissítened kellene valamilyen háttérfolyamattal (cron job), és nem tudnád belőle megmondani, hogy jövő hétre foglalható-e a hely.

A megoldás (és a Senior megközelítés):
Egy parkolóhely státuszát sosem tároljuk, hanem mindig kiszámoljuk a foglalások (Booking) alapján. Ha bejön egy új foglalási kérés mondjuk péntek 14:00-16:00-ra, a backend lekérdezi az adatbázisból, hogy van-e a Booking táblában olyan foglalás ahhoz a helyhez, ami belelóg ebbe az idősávba. Ha nincs, akkor a hely szabad.

Most hozz létre egy models.py fájlt szintén az app mappában. Ide jönnek az általunk megbeszélt mezők. Figyeld meg, hogyan építjük be a type bónusz mezőt, és hogyan kötjük össze a két táblát a ForeignKey-el!

Python
from sqlalchemy import Column, Integer, String, DateTime, ForeignKey
from sqlalchemy.orm import relationship
from .database import Base

class ParkingSpot(Base):
    __tablename__ = "parking_spots"

    id = Column(Integer, primary_key=True, index=True)
    name = Column(String, unique=True, index=True)
    type = Column(String, default="normal")  # pl. "normal", "vip", "disabled"

    # Ez a kapcsolat segít, hogy egy parkolóhelyből könnyen lekérjük az összes hozzá tartozó foglalást
    bookings = relationship("Booking", back_populates="spot")


class Booking(Base):
    __tablename__ = "bookings"

    id = Column(Integer, primary_key=True, index=True)
    parking_spot_id = Column(Integer, ForeignKey("parking_spots.id"))
    applicant_name = Column(String, index=True)
    start_time = Column(DateTime)
    end_time = Column(DateTime)

    # Visszamutató kapcsolat a parkolóhelyre
    spot = relationship("ParkingSpot", back_populates="bookings")

Ha megnézed a hibaüzenet legalsó sorát, ott van a megoldás kulcsa:
FATAL: password authentication failed for user "postgres" at "localhost" (::1)

Ez egy nagyon tipikus, klasszikus Windows + Docker + Python hiba, ami miatt a juniorok (de sokszor a seniorok is) órákig tudják tépni a hajukat. Két dolog okozhatja, oldjuk meg gyorsan!

Mi a probléma?
IPv6 konfliktus (A leggyakoribb): Látod a (::1) részt a hibaüzenetben? A Python (psycopg2) megpróbálja a localhost-ot a modern, IPv6-os hálózaton keresztül feloldani, miközben a Docker általában a hagyományos IPv4-en (127.0.0.1) hallgatja a portot.

Beragadt Docker Volume: Ha a gépeden valaha, bármikor futott már egy másik PostgreSQL Docker konténer postgres_data néven egy másik jelszóval, akkor a mostani indításnál a Docker betöltötte a régi adatokat (és a régi jelszót), figyelmen kívül hagyva a mi új docker-compose.yml beállításainkat.

A megoldás (Két egyszerű lépés):
1. Lépés: Cseréljük le a localhost-ot IPv4-re
Nyisd meg az app/database.py fájlt, és a connection stringben a localhost szót írd át 127.0.0.1-re.
Így kell kinéznie a sornak:

Python
SQLALCHEMY_DATABASE_URL = "postgresql://postgres:postgres@127.0.0.1:5432/parking_db"
2. Lépés: Tisztítsuk ki a Docker Volume-ot (biztos, ami biztos)
Lőjük ki a jelenlegi konténert, töröljük a beragadt adatait, és indítsuk újra tisztán. Futtasd ezeket a PowerShellben:

PowerShell
docker compose down -v
docker compose up -d
(A -v kapcsoló a varázslat: ez törli a postgres_data nevű perzisztens tárat, így most tényleg a mi "postgres" jelszavunkkal fog inicializálódni az adatbázis.)

Újra tesztelés:
Ha ez a két lépés megvan, futtasd újra a szervert:

PowerShell
uvicorn app.main:app --reload
Most már látnod kell az "Adatbázis sikeresen feltöltve alap adatokkal!" üzenetet. Ha lefutott, jöhet a jól megérdemelt commit! Szólj, ha megjavult!

A FastAPI-ban ehhez be kell vezetnünk egy új fogalmat: a Pydantic sémákat.

A models.py felel azért, hogy hogyan néz ki az adat az adatbázisban.

A schemas.py (amit most fogunk megírni) felel azért, hogy hogyan nézzen ki az adat, amikor az API kiküldi vagy fogadja azt JSON formátumban. Ez biztosítja az adatvalidációt.

from sqlalchemy.orm import Session
from typing import List

from .database import engine, SessionLocal
from . import models, schemas

models.Base.metadata.create_all(bind=engine)

app = FastAPI(
    title="Parkolóhely-foglalás API",
    description="Backend szolgáltatás parkolóhelyek kezeléséhez és foglalásához.",
    version="1.0.0"
)

def init_db():
    db = SessionLocal()
    try:
        if db.query(models.ParkingSpot).count() == 0:
            alap_helyek = [
                models.ParkingSpot(name="P-01", type="normal"),
                models.ParkingSpot(name="P-02", type="normal"),
                models.ParkingSpot(name="P-03", type="normal"),
                models.ParkingSpot(name="VIP-01", type="vip"),
                models.ParkingSpot(name="DIS-01", type="disabled"),
            ]
            db.add_all(alap_helyek)
            db.commit()
            print("Adatbázis sikeresen feltöltve alap adatokkal!")
    finally:
        db.close()

init_db()

# Adatbázis session függőség
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

@app.get("/")
def health_check():
    return {"status": "ok", "message": "A Parkolóhely-foglalás API fut és az adatbázis inicializálva!"}

# ÚJ VÉGPONT: Parkolóhelyek lekérdezése
@app.get("/spots", response_model=List[schemas.ParkingSpotResponse])
def get_parking_spots(db: Session = Depends(get_db)):
    spots = db.query(models.ParkingSpot).all()
    return spots

2. Az ütközés (Overlap) logikája
Mikor mondjuk azt, hogy egy új foglalás ütközik egy már létezővel?
Két idősáv akkor fedi egymást, ha a már bent lévő foglalás kezdete korábban van, mint az új foglalás vége, ÉS a már bent lévő foglalás vége később van, mint az új foglalás kezdete.

Ezt az SQL lekérdezést fogjuk beépíteni a végpontba.

# ÚJ VÉGPONT: Foglalás leadása
@app.post("/bookings", response_model=schemas.BookingResponse)
def create_booking(booking: schemas.BookingCreate, db: Session = Depends(get_db)):
    
    # 1. Alapvető validáció: a vége nem lehet a kezdete előtt
    if booking.end_time <= booking.start_time:
        raise HTTPException(status_code=400, detail="A záró időpontnak a kezdő időpont után kell lennie.")

    # 2. Ellenőrizzük, hogy létezik-e egyáltalán a kért parkolóhely
    spot = db.query(models.ParkingSpot).filter(models.ParkingSpot.id == booking.parking_spot_id).first()
    if not spot:
        raise HTTPException(status_code=404, detail="A megadott parkolóhely nem létezik.")

    # 3. Ütközésvizsgálat (Overlap logic)
    overlapping_booking = db.query(models.Booking).filter(
        models.Booking.parking_spot_id == booking.parking_spot_id,
        models.Booking.start_time < booking.end_time,
        models.Booking.end_time > booking.start_time
    ).first()

    if overlapping_booking:
        raise HTTPException(status_code=400, detail="A parkolóhely ebben az időszakban már foglalt.")

    # 4. Ha minden rendben, elmentjük az új foglalást
    new_booking = models.Booking(
        parking_spot_id=booking.parking_spot_id,
        applicant_name=booking.applicant_name,
        start_time=booking.start_time,
        end_time=booking.end_time
    )
    
    db.add(new_booking)
    db.commit()
    db.refresh(new_booking) # Frissítjük az objektumot, hogy megkapja a generált ID-t
    
    return new_booking

import os
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker, declarative_base

# Ha a Docker átadja a DATABASE_URL-t, azt használja, ha nem, marad a lokális 5433-as teszteléshez
SQLALCHEMY_DATABASE_URL = os.getenv(
    "DATABASE_URL", 
    "postgresql://postgres:postgres@127.0.0.1:5433/parking_db"
)

engine = create_engine(SQLALCHEMY_DATABASE_URL)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)

Base = declarative_base()
2. A Dockerfile létrehozása
Hozz létre egy új fájlt kiterjesztés nélkül, pontosan Dockerfile néven a projekted legkülső mappájában (ott, ahol a requirements.txt is van). Másold bele ezt:

Dockerfile
# Hivatalos, pehelysúlyú Python image-t használunk
FROM python:3.11-slim

# Munkakönyvtár beállítása a konténeren belül
WORKDIR /code

# Függőségek másolása és telepítése (így a Docker tudja cache-elni ezt a lépést)
COPY ./requirements.txt /code/requirements.txt
RUN pip install --no-cache-dir --upgrade -r /code/requirements.txt

# A teljes app mappa bemásolása
COPY ./app /code/app

# A szerver indítási parancsa
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
3. A docker-compose.yml frissítése
Most nyisd meg a már létező docker-compose.yml fájlt, és írd felül ezzel az új tartalommal. Ezzel teljesítjük a feladat elvárását, miszerint a teljes rendszer (adatbázis és kód) egyszerre, egy paranccsal induljon.  
PDF

Figyeld meg a web szolgáltatás alatti environment részt: itt mondjuk meg a Pythonnak, hogy a belső hálózaton a db nevű, 5432-es porton lévő géphez csatlakozzon!

YAML
services:
  db:
    image: postgres:15-alpine
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: parking_db
    ports:
      - "5433:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data

  web:
    build: .
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=postgresql://postgres:postgres@db:5432/parking_db
    depends_on:
      - db
    restart: on-failure

volumes:
  postgres_data:
4. A nagy teszt!
Ments el minden fájlt! Mivel a database.py is megváltozott, és ezt eddig nem rögzítettük, előbb csinálj egy Git commitot:

PowerShell
git add .
git commit -m "Dockerize application: Add Dockerfile, update DB config, and setup web service in docker-compose"
Ha a commit megvan, állíts le mindent (ha még futna valamilyen szerver a terminálodban). Lődd le a korábbi Docker adatbázist is, hogy tiszta lappal induljunk:

PowerShell
docker compose down
És most jöhet a varázslat. Add ki ezt az egyetlen parancsot:

PowerShell
docker compose up --build -d
(A --build kapcsoló azért kell, hogy a Docker megépítse a Python konténerünket a friss Dockerfile alapján, a -d pedig továbbra is a háttérbe küldi a folyamatot.)

Ha lefutott, nyisd meg böngészőben a [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs) oldalt. Ha bejön a Swagger UI, és hiba nélkül le tudod kérdezni a GET /spots végpontot, akkor hivatalosan is összeraktál egy teljesen konténerizált Full-Stack (Backend + DB) alkalmazást!
